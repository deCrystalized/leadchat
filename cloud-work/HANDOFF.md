# LeadChat — точное продолжение работы в облаке

Это рабочий пакет для продолжения разработки, не готовый релиз. Один исполнитель, без субагентов и других coding-сессий. Пользователь разрешил выбрать удобное приватное место для переноса. Репозиторий: deCrystalized/leadchat, ветка codex/leadchat-design-cloud-2026-10-31.

## Что продолжать

Полностью подготовить новый дизайн к работе в LeadChat без потери функций: прочитать оставшийся runtime и связанные нативные модули, сопоставить реальные функции и права, исправлять подтверждённые ошибки с содержательными регрессиями, проверять сборки и пользовательские сценарии. Сохранять исходный смысл статистики, уведомлений, источников, чатов, ролей, черновиков, очередей и интеграций. Пользователь просит удобный, чистый, узнаваемый интерфейс, плавную работу и минимум текста без функционального смысла.

Работать только с извлечённым кандидатом. `reference/` — неизменяемый снимок исходников для сравнения и тестов; не редактировать его. Никаких production/server/SSH/provider/customer/CRM/Telegram/MAX-записей, реальных отправок, удалений источников, деплоя или активации новых платных провайдеров. Не менять существующую политику «Отошёл», AutoAway, возврата по активности, release или распределения MAX: новая политика пока только обсуждена. Не ослаблять тесты ради зелёного результата и не объявлять абсолютное отсутствие ошибок. Не повышать права и не выводить секреты. Модель/усилие не понижать; конфигурация владельца gpt-6.1-sol/ultra.

## Подготовка

В этой ветке сохранён каталог `cloud-work/`. В корне клонированного репозитория выполнить:

```sh
python3 cloud-work/prepare.py
cd design-workspace/frontend
npm ci
npm run typecheck
npm run lint
npm run test:transfer
```

`prepare.py` проверяет каждую часть архива, каждый файл и итоговый отпечаток frontend. Он распаковывает только отсутствующие или побайтово совпадающие файлы. При отличии уже извлечённого файла останавливается, не затирая работу. Не повторять распаковку поверх изменённого кандидата; использовать уже извлечённое рабочее пространство.

Сборки выполнять в явно заданные отдельные outDir. Сначала прочитать фактические package.json, vite/vitest и tools кандидата; не запускать `prepare:transfer` с путями по умолчанию. На облачной среде Node должен удовлетворять закреплённым Vite/React-плагинам; локально используемые версии записаны в manifest.json. Rust/Windows и физическую экранную клавиатуру нельзя считать проверенными Linux-тестами.

```sh
npm run build -- --outDir ../build/web
npm run build:preview -- --outDir ../build/preview
npm run build:candidate -- --outDir ../build/candidate
npm run build:desktop -- --outDir ../build/desktop
npm run build:desktop-candidate -- --outDir ../build/desktop-candidate
```

Для полного набора нужен `VITE_LEADCHAT_REFERENCE_ROOT` с абсолютным путём к извлечённому `design-workspace/reference`, `VITE_CANDIDATE_HTML` к точному собранному index.html и `VITE_CANDIDATE_CSP` к подготовленной CSP. Прочитать `docs/mobile-thread-profile/verify-final.py`: там записана процедура CSP и фактические проверки. Старые абсолютные пути в отчётах — историческое свидетельство; в облаке выбирать фактические пути явно. Не заменять отпечаток референса содержимым старой ветки main.

## Следующие шаги

1. Воспроизвести на настоящем ChatsPage потерю caret при пересечении mobile/desktop: текст сохраняется, курсор становится 0. Изолированный ThreadPane это не покрывает.
2. Проверить позднее завершение `dispatch.ts::шагПоСписку`: догрузка страницы может увести назад после перехода в другой раздел/диалог. Сначала полностью прочитать `списокНаЭкране.ts` и существующие тесты; гипотеза ещё не доказана.
3. Воспроизвести уход фокуса в body после inline-действия статуса профиля; проверить hotkeys/help modal/session retirement и отложенные actor ACK. Не считать их уже исправленными.
4. Проверить channel-aware текст гостевого предупреждения: в MAX сейчас встречается «отозвать его в Авито нельзя». Менять текст без изменения маршрутизации провайдера.
5. Продолжить оставшийся ручной runtime/native аудит по ledger. Не выдавать копирование файлов, хеш или урезанное чтение за полное ручное ревью. Три файла основаны на прежнем полном чтении плюс полном текущем diff; это указано отдельно.
6. Разобрать 96 старых падений по функциональному смыслу; не восстанавливать устаревшие селекторы вслепую. Пройти всю карту функций и ролей, сценарии источников/удалений/статистики/уведомлений/очередей/кэша, точный пакет переноса и откат. Дополнительные старые задачи: coworker outgoing scroll, note/takeover ACK ownership, cold statistics skeleton/chart heights, journal offset/heatmap contracts.

Планы продукта, функциональные карты, Away/notification proposals, регрессии и открытые условия — в `docs/line/`. Последний подробный этап — в `docs/mobile-thread-profile/`. Ledger — там же. Перед каждым изменением читать реальные зависимости, после — целевые проверки и весь итоговый diff тем же исполнителем. Не называть это независимым ревью. При длительной работе обновлять PLANS.md фактами и следующими шагами.

## Статус переноса

Само наличие пакета/ветки не означает, что облачная задача запущена. На момент подготовки доступных Codex Cloud environments нет. Попытка открыть chatgpt.com для настройки отклонена origin approval gate; обходить отказ запрещено. Владелец должен создать/опубликовать приватную среду с этой веткой и запустить продолжение. Только успешный старт с проверенным sourceSnapshot подтверждает работу при выключенном Mac. До этого работа остаётся локальной.
